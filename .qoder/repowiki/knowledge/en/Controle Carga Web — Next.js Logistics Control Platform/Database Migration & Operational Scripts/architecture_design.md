Flat collection of executable scripts under `scripts/` plus raw DDL/DML under `sql/`, organized by purpose rather than strict layers. Scripts fall into several functional groups: (1) Prisma bootstrap helpers in `scripts/prisma/` (`generate.js`, `init-prisma.js`) that run `npx prisma generate --no-engine` with production-safe env flags; (2) a shared Prisma client in `scripts/util/prismaScriptClient.ts` that reads `DIRECT_URL` or `DATABASE_URL` and is reused by many scripts; (3) data migration and fix scripts (e.g. `sync-production-db.ts`, `apply-migration.ts`, `executar-migracao-producao.js`, `fix-*.js`) that connect to Postgres via Prisma's `$executeRawUnsafe` / `$queryRaw` to apply SQL files or perform record-level corrections; (4) diagnostic/check scripts prefixed `check-`, `debug-`, `diagnostico-`, `verificar-` that inspect tables, enums, users, transportadoras, etc.; (5) seed/admin creation scripts (`seed.ts`, `create-admin.*`, `criar-admin.ts`); and (6) test scripts prefixed `test-*` exercising APIs or DB state. Raw SQL migrations live in `sql/` and are either applied directly from JS scripts or executed manually against production. Dependency direction is one-way: scripts depend on `@prisma/client` and environment variables; there is no internal module graph between scripts — each file is self-contained and invoked individually via `node` or `ts-node`.
