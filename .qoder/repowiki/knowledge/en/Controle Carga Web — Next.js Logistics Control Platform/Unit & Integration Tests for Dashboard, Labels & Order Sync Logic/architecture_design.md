Tests live at the repository root under `tests/` and are executed directly by Node's built-in test runner (`node:test`). Each file targets a single domain: `labels.test.ts` validates barcode validation, ZPL label generation and PDF page-count helpers; `dashboard-freshness.cjs` uses TypeScript transpilation + `vm.runInNewContext` to load `lib/dashboard-freshness.ts` and a React hook in isolation, mocking `react`, `localStorage`, and the freshness module; `pedido-cards.test.ts`, `pedido-pendencias.test.ts`, and `pedido-sincronizacao.test.ts` assert pure functions from `lib/pedido-*`; `sincronizacao-lotes.test.ts` is an integration-style test that stubs Prisma methods (`findMany`, `upsert`) and `apiExternaService` to exercise `sincronizarLogisticaSnapshot` end-to-end without a real database or ERP. All tests import production code via relative paths or `@/...` aliases resolved by the project's tsconfig, keeping the test layer thin and focused on assertions.
