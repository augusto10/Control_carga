Two sibling sub-folders with distinct responsibilities:
- `types/` is a pure type layer. It re-exports domain models derived from `@prisma/client` (e.g. `INotaFiscal`, `IControleCarga` in `index.ts`), defines DTOs (`CriarControleDTO`, `AdicionarNotaDTO`), user/auth shapes (`auth-types.ts`), system configuration types (`prisma-types.ts`), label/barcode/printing contracts (`labels.ts`), and generic API response envelopes (`api.ts`). Third-party ambient declarations live in `*.d.ts` files (`jsonwebtoken.d.ts`, `next-auth.d.ts`, `qz-tray.d.ts`, `react-input-mask.d.ts`) so the rest of the app can import those modules without bundling their own typings.
- `store/store.ts` declares the shared Zustand store (`useStore`) with state slices for `notas`, `controles`, `transportadoras`, plus a `status`/`loading` flag and async actions (`fetchNotas`, `fetchControles`, `addNota`, `criarControle`, `vincularNotas`, `finalizarControle`, `atualizarControle`, `deleteNota`). Actions call backend endpoints directly via `fetch` (and one path via an Axios `api` instance) against `/api/*` routes, dispatch `set()` to mutate local state, and surface errors by throwing typed `Error` objects. The store is the single source of truth consumed by UI components across the app.
