Built on the legacy Next.js `pages/` router. `_app.tsx` is the single entry point that wraps every route with MUI `ThemeProvider`, a custom glassmorphism `SnackbarProvider` (notistack), `AuthProvider`, `ConfiguracaoContext`, and a `ProtectedRoute` wrapper; public routes (`/login`, `/esqueci-senha`, `/cadastro`) bypass protection while others render inside `AppLayout`. Page components opt into the layout by setting a static `usesAppLayout = true` flag (e.g., `admin/index.tsx`). The `pages/api/` directory mirrors business domains — `auth/*` handles JWT login/logout/profile via bcrypt + jsonwebtoken + Prisma, `admin/*` serves dashboard stats and health checks, `pedidos/*`, `notas/*`, `controles/*`, `etiquetas/*`, `relatorios/*`, `motoristas/*`, `usuarios/*`, `solicitacoes-material/*`, `ssw_accert/*`, and `baixar-entregas/*` expose REST-like handlers that pages call with `fetch('/api/...')` using `credentials: 'include'` cookies. Each domain folder groups related handlers (index, `[id]`, sub-actions like `aprovar.ts`/`rejeitar.ts`), keeping request handling co-located with its feature area. Client pages consume these endpoints directly from React components rather than through a shared client SDK.
