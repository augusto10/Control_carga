The module is a flat collection of domain-scoped service modules, each wrapping one external system or concern:
- HTTP clients: `api.ts` exports an Axios instance configured with base URL resolution (`NEXT_PUBLIC_API_URL`), XSRF cookie handling, request/response interceptors that inject `Authorization` from cookies and redirect on 401; `api-externa.ts` wraps the external ERP at `API_EXTERNA_BASE_URL` with its own token lifecycle (`/token` login, in-memory token cache, retry block after failures) and typed methods for notas fiscais, pedidos, clientes, dashboard.
- SSW integrations: `sswClient.ts` handles JSON-based SSW API calls with cached tokens (`getSswToken`) and also talks to a separate external nota-fiscal endpoint; `sswPortalClient.ts` performs full browser-like session management against `https://sistema.ssw.inf.br`, including HTML form login, cookie persistence per account (ACCERT / EXPRESSO_GOIAS / ZANUELLO), HMAC-signed photo URLs, and HTML parsing of CTRC occurrence tables; `sswTracking.ts` is the aggregation layer that runs both `trackingDanfe` and `trackingPortalByNotaFiscal` in parallel and normalizes their heterogeneous responses into a single `SswTrackingResult` shape.
- Printing & labels: `qz-print.ts` connects to the QZ Tray desktop bridge via WebSocket, lists local printers, and sends raw ZPL; `product-label-pdf.ts` builds A4 sheets with two 180×110 mm product labels using `pdf-lib` and `jsbarcode` entirely in the browser.
- Business helpers: `roteirizacao.ts` groups NFs into routes/boxes by city/bairro/logradouro; `geocoding.ts` queries OpenCage with retries and localStorage caching; `gamificacaoService.ts` calls `/gamificacao/*` endpoints for scoring/ranking.
Dependency direction is one-way: higher-level services (`sswTracking.ts`) compose lower-level clients (`sswClient.ts`, `sswPortalClient.ts`); business logic (`roteirizacao.ts`) consumes data models from `api-externa.ts`; nothing in this folder imports UI components.
