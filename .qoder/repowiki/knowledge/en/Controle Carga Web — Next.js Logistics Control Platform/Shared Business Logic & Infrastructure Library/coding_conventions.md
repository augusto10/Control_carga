- External API responses are normalized through small helper functions that try multiple field name variants (snake_case, UPPER_SNAKE_CASE, camelCase) before falling back to null, keeping callers free of source-specific shape assumptions.
- Database access uses `prisma.$queryRawUnsafe` with explicit column lists and parameterized placeholders instead of Prisma model methods, allowing conditional column inclusion and safe batching via IN clauses split into blocks of ~200.
- Process-scoped caches are implemented as module-level `Map` instances keyed by a composite string (e.g. username + limit + filters), with separate `expiresAt`/`staleAt` timestamps to support soft-stale reads and concurrent request deduplication via a pending-promises map.
- Authentication is performed by extracting a token from either the `auth_token` cookie or an `Authorization: Bearer <token>` header, then verifying with `jsonwebtoken` against `JWT_SECRET` and resolving a user row from Prisma.
- ZPL generation treats label dimensions, darkness, and barcode types as module constants and builds pages by concatenating command arrays, validating barcodes through `analyzeBarcode` before emitting any output.
- Each domain concern lives in its own single-file module exporting pure async functions, with no shared base class or DI container — composition happens at the caller side by importing multiple lib files.
