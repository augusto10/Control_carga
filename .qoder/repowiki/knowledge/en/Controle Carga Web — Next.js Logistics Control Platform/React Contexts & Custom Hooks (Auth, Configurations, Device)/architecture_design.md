Two parallel layers: `contexts/` holds React Context providers that own global state, while `hooks/` exposes reusable logic consumed by components. The primary auth flow lives in `AuthContext.tsx`, which wraps state via `useState`/`useCallback`/`useMemo`, persists tokens through `js-cookie` (HTTP-only cookie strategy) and validates sessions by polling `/api/auth/me` every 5 minutes; a secondary, simpler `AuthProvider.tsx` in the same folder uses `nookies` and is kept for compatibility. `ConfiguracaoContext.tsx` composes the `useConfiguracoes` hook to load admin settings from `/api/admin/configuracoes` only when authenticated, exposing typed getters (`getConfig<T>`) and bulk updaters. The hook layer is split by concern: `useAuth.ts` is a build-time placeholder stub; `useConfiguracoes.ts` centralizes CRUD over system config with type coercion (string/number/boolean/json); `useCurrentDashboard.ts` caches dashboard responses in `localStorage` keyed by a cache key and guards updates via `canReplaceDashboard`; `useDeviceDetect.ts` detects mobile/Android/iOS/camera/scanner via `navigator.userAgent` and MUI breakpoints; `useDevicePermissions.ts` requests camera permissions through `getUserMedia`; `useResponsiveStyles.ts` derives spacing, typography, layout, and component dimensions from the detected device size and MUI theme. Dependency direction is one-way: contexts depend on hooks, hooks depend on `services/api` and shared libs (`@/lib/*`), and nothing in this module imports UI pages.
