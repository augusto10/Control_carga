The module is split into three sibling areas with no internal dependencies between them:
- `utils/` — runtime helpers consumed by API routes and server scripts. `auth.ts` exports a single `getTokenFromCookies` helper typed against Next.js `NextApiRequest`. `cn.ts` wraps `clsx` + `tailwind-merge` as the project's shared class-name utility. The remaining JS files are Node-only: `printer.js` builds shipping labels via `pdf-lib` (PDF) and raw ZPL strings sent through `child_process` (`copy /b`) to Windows printers; `printer-integration.js` exposes a `PrinterIntegration` class that detects printers via WMIC on Windows and falls back to mock printers on other platforms; `logo-generator.js` uses `sharp` to rasterize `public/templates/logo oficial.png` into a monochrome `.GRF` file consumable by Zebra printers.
- `styles/` — global CSS entry importing Tailwind (`@import "tailwindcss"`, `@config "../tailwind.config.js"`) plus two base/component layers (`card-shadow`, `glass`). `theme.ts` defines a full MUI `createTheme` (palette, typography, component overrides for Button/Card/Paper/TextField/AppBar/Drawer/etc.) used as the app-wide design system.
- `src/theme/professionalTheme.ts` — a smaller, alternate MUI theme (orange/dark palette) exported as default, kept separate from the heavier `styles/theme.ts` so different pages or contexts can swap themes.
Dependency direction is one-way: UI code imports from `styles/*` and `src/theme/*`; server-side code imports from `utils/*`; nothing in `utils/` imports from `styles/` or `src/`.
